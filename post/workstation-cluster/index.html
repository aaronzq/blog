I Built a LAN of workstations for parallel image processing

Aaron
2024-07-17
electronics

I recently need to process a massive timelapse dataset that consists of 480,000 frames. The processing algorithms was built in Matlab and takes about 24 seconds per frame even with the GPU acceleration. The total amount of time is madness and defintely beyond the time budget of my project.

My lab has several GPU workstations with decent memory and cpu cores. The computation guy who has used them graduated so long ago and now they are simply eating dust. Despite not being the recommended way[1,2], I run a parfor that calls the GPU-based image processing algorithm for different frames. It works. It handles as many as 16 (the # of CPU cores on the machine of test) images without introducing obvious parallel computing overhead. I don’t actually know when the performance will start degrading. Maybe it’s because of the large GPU memory (RTX 3090, 24GB). But anyway, it provides a simple solution to dramatically reduce the total processing time, and is even better if I can wire up all other available workstations together.

There are three of them. Originally I plan to copy the data to each of them before running codes. But it just sounds more convenient if the procedure can be more automated.

Set up a shared drive among workstations

The first thought is to set up a Network Attached Storage (NAS) but I soon realized that the shared drive can be easily hosted on any computer in the local netwrorks [3]. For example, a Windows PC can share a folder on its own local drive and other workstations, no matter whether they are linux and macos, can have access to it. It is even better than NAS in my opinion, considering that I can host the shared drive on the main computer I daily use. It saves the routine download/upload with the separate NAS. I can thus check the results during processing just like I run code locally on this computer. If the image processing requires collaboration, NAS could be a better solution.

My steps

  1. Get a gigabit router/switch (TP-Link Tri-Band BE9300) and connect workstations with cables. The workstations have 2.5G ethernet ports so I make sure the router and cables support at least this speed.
  2. On the daily Windows workstation, I configurate this local network (provided by router) to be private network and enable files sharing in private network through the network setting.
  3. Create a dedicated folder, for example, “SharedFolder”. Right click it and share to the current user. The current user name and password are the ones used to log in my Windows computer, e.g. username: rabbit. Note down the IP address in local network, e.g. 192.168.1.1
  4. Install Ubuntu on the other workstations. Check the router (e.g. at its portal page, 192.168.0.1) and make sure the other workstations appear in the LAN with proper IP adresses. Create a folder to mount the shared drive. To mount, open the terminal and input: The terminal will ask for the password. The shared folder can then be found in this workstation and accessbile just like local drive.

Automate the distributed computing job

The reason why I set up most of workstations in Linux is that I want them to be remotely controlled and monitored conveniently. If they are Windows, the only way I know is to remote desktop them, open the Matlab application and run the codes. The GUI application will take many human inputs and also occupy lots of network bandwidth for continuous monitoring.

The preferred way will be that, for every job (i.e. every large dataset processing),

  1. On the daily Windows workstation, I put the data in the shared drive;
  2. Create a configuration file that partitions the dataset into several groups. The configuration files will be generated and stored in the shared drive for other workstations to access;
  3. Connect each remote workstation via SSH and run a single command that instructs them to run code in terminal according to the configuration file. It processes one part of the dataset;
  4. Keep the SSH windows open and monitor the progress

The SSH part is easy. Download and install OpenSSH if it’s not there.

The image processing code also needs some modification to work with external configuration file. The only function of the configuration file in my case is to tell each workstation which range of frames to process. But it is easy too.

The difficult part for me is to write bash script to run Matlab code in terminal and keep the human inputs as few steps as possible.

To make the alias persistent we can declare it in ~/.bashrc and ~/.bash_profile. It’s similar to putting the application directory in the PATH environment varibale in Windows.

The difference between .bashrc and .bash_profile is when they are executed: .bashrc is executed for non-login interactive shell, such as openning the terminal app, and .bash_profile is execute for login interactive shell, such as when we connect using SSH. The ‘interactive’ means that the you and shell talk to each other instead of shell running by itself. Running a .sh script is not interactive. Variables

  • The second thing is the variable. After defining a varibale, the dollar sign $ can be used to expand it. ${var} is a disambiguation mechanism that works same as $var. So you can use ${var}text when you want to append string text to the contents of the variable var and run the resulted string as a new command (as opposed to $vartext which only means the contents of the variable vartext).

  • Closely related is the command $(...). However, it it not used to expand the variable but to run what’s inside the () as a command and put its output here. See here.

  • Besides, everything following an open single quote ' is quoted literally, up until the next ' which is taken as the closing quote. In contrast, several kinds of shell expansions are performed inside double quotes ", including varible expasion $var and ${var}. See here.

Write a script

Script contains a series of bash commands. Running the script file will execute these commands so that we don’t need to perform them one by one. The script can take arguments: $1 and $2 and so on will be the first and second input variable, respectively. I used a simple script that takes an integer to specify which configuration file to use. And then it runs the command in Matlab without GUI. Let’s save this script in root folder as matlab_script.sh.

And then for each workstation I made a different alias. The alias sends in 1 to matlab_script.sh on workstation 1 and 2 to workstation 2.

In this way, I am able to simply type a recon command in the ssh session and the connected workstation will pick up a different configuration file and run the matlab program. Of course the configuration files have to be manually created by us and put in the ‘RUN/‘ directory in the shared folder.
